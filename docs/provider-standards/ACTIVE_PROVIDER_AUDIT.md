## Coverage cautions

Existing repository tests are evidence of specific files/cases, not a blanket conformance badge. Some assertions still describe older manifest/provider versions (e.g. a standalone NetMirror 1.4.0 activation checkpoint), while the active fast route is 2.0.2. This update does not rewrite historical tests or claim all legacy suites were rerun successfully. Relevant source/test paths and immutable source hashes are recorded with this audit; the new standards suite tests the reusable tools themselves.

The WCO 205 suite remains in the preserved local development/review package and was rerun as an extra no-regression check for this task. That does not make it automatically available after a fresh Nexus clone. A future authorized test-publication task can add reviewed, sanitized provider fixtures/suites; do not upload private captures or claim missing fixtures are installed.

## Diagnostic compatibility conclusions

HTTP-image diagnostics are demonstrably eligible under the inspected source predicates despite DIAG/INFO labels. This is directly reproduced for AniKoto and KissKH in the entry-failure probe; Tubi and Re:ANIME contain transitive affected paths requiring focused reachability tests. WCO's exact sentinel is conditionally excluded, but its broad presence flag is true and native behavior remains a separate gate. See the compatibility report before any migration.

No P0 credential leak or wrong-episode incident was established by this audit. Raw error-snippet paths are a **potential** disclosure risk needing seeded secret tests, not a claim that user credentials leaked. Nonblocking audit findings must not trigger unapproved automatic normalization or provider-wide changes.
